2026年7月26日 API 中心重构任务（以本文件为最新 API 任务）

目标：把当前“API1/API2/图片 API/服务配置库/模型选择/双 API”重构为用户能理解、可追踪、可维护的 API 中心。保留小米 MiMo 直售、MiMo 订阅、DeepSeek、用户自定义和网络动态模型能力。

一、P0 安全与行为收敛
[x] API1/API2 仅作为兼容层，界面改称“主服务/备用服务/图片识别服务”。
[x] 双 API 默认关闭；只有计算核对、分类核对、报告对比等明确任务允许开启，并提示调用次数、费用和耗时会增加。
[x] 明确三种路由：指定服务、自动切换、双 API 核对。
[x] 指定服务失败时禁止静默换接口；自动切换只允许处理超时、429、5xx，并显示实际来源和切换原因。
[x] 401/403、模型不存在、地址错误、协议不兼容、图片能力不足不得自动切换。
[x] API Key 默认遮罩，禁止出现在普通日志、错误信息、诊断导出和备份中；接入 Android Keystore，业务 JSON 只保存密钥引用。
[x] 应用启动和普通页面进入不自动发起 API 检测；检测全部必须由用户明确触发。

二、P1 API 中心页面
[x] 新增统一“API 中心”，顶部显示普通问答、批量解析、图片识别、核对、报告的当前实际路由和健康状态。
[x] 服务连接区只管理服务/账号连接：名称、供应商、Base URL、协议、密钥引用、最近检测、延迟、能力和错误状态。
[~] 任务路由区管理每类任务使用哪个服务、哪个模型、失败策略和是否允许本次覆盖。（已完成任务服务与失败策略；任务级模型覆盖和本次临时覆盖待做。）
[x] 调用记录区记录实际服务、实际模型、耗时、成功/失败、备用切换和错误分类。
[x] 删除“保存当前”和“应用到 API1”重复流程，统一为编辑器保存 + 路由分配。
[x] 设置页、全局助手、助手页、物种图片识别、预览报告和计算核对全部复用同一个路由控制器。

三、P1 添加服务与模型
[~] 添加服务改为向导：选择厂商模板 -> 填 Key/地址 -> 测试连接 -> 拉取并智能推荐模型 -> 搜索/选择模型 -> 检测能力；路由分配在保存后由“当前任务路由”完成。
[x] 预置只提供连接地址和协议，不预设模型名；模型始终从网络获取，保留手动填写入口。
[x] 模型列表仅保留本次编辑会话，支持搜索和智能推荐；当前模型不会被刷新静默覆盖，服务商下线模型不会被本地缓存重新带回。
[x] 获取模型失败时保留上一次选择，不清空模型；错误提示保留服务端状态与响应详情。
[x] 记录模型能力：文本、图片、结构化 JSON、长上下文；未验证能力不得伪装成支持。
[x] MiMo 订阅风险提示绑定到服务配置并记录用户确认状态，后续编辑仍可查看。

四、P2 路由与任务体验
[ ] 每个任务入口显示“本次使用：自动/指定服务/双 API”，默认跟随全局路由。
[ ] 支持任务级临时覆盖，任务结束后自动恢复默认，不污染全局配置。
[ ] 图片识别只展示已验证视觉能力的模型；多图任务显示预计调用数量、失败重试和实际来源。
[ ] 双 API 结果并排展示，必须由用户确认采用结果，AI 不得直接写入数据。
[ ] API 失败结果提供可执行动作：重试、切换备用、编辑配置、跳过本次。

六、验收标准
[ ] 新用户只配置一个服务即可完成普通问答、批量解析和导出报告。
[ ] 用户能在任意任务入口一眼看到实际调用的服务和模型。
