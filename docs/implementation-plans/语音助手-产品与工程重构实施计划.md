# 语音助手产品与工程重构实施计划

> **实施流程：** 可按任务复杂度选择合适的开发、调试和验证流程；不得把任何特定工具或工作流作为项目功能开发的强制前置条件。每个复选框仅用于跟踪，不替代代码、测试和人工验收。

**目标：** 将语音识别助手从“配置很多的转写工具”收敛为可靠、安全、可恢复的现场语音采集与主 App 指令交接工具。

**架构：** 保留 Whisper、Sherpa、本地转写和主 App 最终确认写库的边界。对外提供通用“授权伙伴转写 API”，由可信 UID、包名和签名摘要建立可撤销会话；浮游动物一体化只是预置且同证书的 `plankton-v1` 领域 Profile，可少一次确认但不拥有另一套私有协议。后台实际转写服务不再对外暴露；一个 `TranscriptionController` 取代 `MainActivity` 与 `RequestActivity` 的重复队列/录音/结果逻辑，页面只装配不同场景的 UI。

**技术栈：** Kotlin、Jetpack Compose、DataStore、Room、WorkManager、Android Keystore、whisper.cpp、Sherpa ONNX、JUnit、Compose 语义测试、Android Macrobenchmark/Perfetto。

## 全局约束

- 本计划不改变主 App `v7.2 (720)` 的发布包；主 App 只接收语音助手结果并继续展示动作预览，绝不绕过确认直接写入数据集。
- `3.5/3.6/3.7` 是源代码里程碑，不是三次发布。中间只运行定向单元测试、lint 和编译验证，不递增版本、不生成 Release APK、不更新加密文档、不创建 GitHub Release。
- 所有里程碑验收完成后只发布一次语音助手 `v3.7 (37)`；届时使用主 App 已验证的正式证书，旧 Debug 签名语音助手首次迁移需要卸载一次。
- `minSdk` 保持 `34`；`compileSdk/targetSdk` 升级集中在 v3.7 的最终验收前完成，不能夹带到前两个里程碑。
- 不保留明文语音、转写文本、调用方签名或授权记录到 Android 自动备份；默认保留期 24 小时，用户可立即删除。
- 不使用 ADB 模拟点击；单元/集成/构建自动验证后由用户进行真机录音、悬浮窗和跨 App 人工验收。
- 签名私钥只存在 `D:\plankton\.secrets\release-signing\`，`api_backups/`、语音缓存、模型和构建产物不得提交。
- 继续支持已经发布的 v1 Intent `BridgeRequest`/`BridgeResult`，但它只能打开用户可见的核对页面，不能再触发开放的后台转写。v2 以受授权绑定会话为首选通道，直至 v3.7 后仍保留 v1 兼容期。
- 公开 API 只有通用转写、进度、取消和结果能力；`plankton-v1` 只是经过校验的领域上下文/Profile，不允许第三方上传可执行插件或远程代码。

## IPC 与文档审计结论

- 现有 `voice_assistant/bridge/.../VoiceAssistantContract.kt` 与主 App `android/app/.../voiceassistant/VoiceAssistantContract.kt` 都维护同名字段，且没有机器可验证的规范、版本协商、长度上限或错误码表；必须建立单一 JSON 契约向量和两端兼容测试，防止字段静默漂移。
- v1 请求完全相信 `return_package`、`return_action` 和 `audio_uri` Extra；`RequestActivity` 虽展示包名/签名并允许授权，但后台 `TranscribeService` 是导出的，不能把请求 Extra 当成调用方身份。
- v1 文档将“开放第三方接入”与“后台转写”写在同一安全建议下，却没有说明通用伙伴的发现、授权、能力、会话、限流、取消、回调、数据保留或弃用策略；且第 6 节存在重复的 `6.2` 标题。
- v2 必须将“通用音频转写”与“领域特调”分开：`generic` 不需要浮游动物数据；`plankton-v1` 只接受已定义的点位、物种别名和动作预览上下文。未来别的 App 以新的 Profile JSON 注册字段映射和词表，不能注入代码。

v1 Intent 保留为兼容入口：未知调用只能进入人工确认页，不能直达 `TranscribeService`；v1 回调不授予额外能力。v2 结果通过绑定会话的 `IPartnerCallback` 返回，替换可伪造的 `return_action`/`return_package` 广播。所有请求携带 `requestId`、`clientNonce` 和会话绑定的 idempotency key；错误码固定为 `AUTHORIZATION_REQUIRED`、`TOKEN_EXPIRED`、`AUDIO_UNREADABLE`、`MODEL_UNAVAILABLE`、`RATE_LIMITED`、`CANCELLED`、`INTERNAL_ERROR`。

## 总体验收

1. 浮游动物一体化以预置 `plankton-v1` Profile 经受信任会话调用；其他 App 可通过用户授权进入通用 `generic` Profile，并只能使用被授予的范围。未授权、换签名、过期会话、越权取消和伪造回调均失败。
2. 录音/转写过程中进程重建后，任务能恢复为可继续或可取消状态；用户可以删除音频、历史和诊断，自动备份不包含它们。
3. 主页面、接入页和悬浮窗共享同一任务状态；队列、取消、重试、质量与结果不会因切页产生两份记录。
4. 快速发送和核对后发送均能完成“录音 -> 转写 -> 主 App 动作预览”，任何模式均不自动写入数据集。
5. 基准语料持续报告文本错误率、动作完全匹配率和 p95 耗时；新模型或 Android 平台升级未达预算不得发布。
6. 3.5/3.6/3.7 每个内部里程碑只运行相关测试、lint 和编译验证；所有事项完成后才进行一次 `v3.7 (37)` 的签名、版本/文档同步、APK 发布和用户真机验收。本计划中的事项全部完成前不宣称“语音助手正式可公开分发”。
